# Deploying QP2 Data Portal

Production deployment of the GM/CA Data Portal at `https://www.gmca.aps.anl.gov/data_portal`.

## Architecture

```
Browser → HTTPS → Apache (www.gmca.aps.anl.gov)
                    ├── /data_portal/         → Static files (React build)
                    └── /data_portal/api/*    → Proxy to Backend (127.0.0.1:8000)
                                                  ├── FastAPI / Uvicorn
                                                  ├── MySQL (bl2upper / gmca_accounts)
                                                  ├── Redis (analysis results)
                                                  ├── BeeGFS (/mnt/beegfs/DATA)
                                                  ├── Model Storage (/mnt/beegfs/dmadmin/models/)
                                                  └── Slurm (AF3 prediction jobs → gpu partition)
```

## Prerequisites

- Apache with `mod_proxy`, `mod_proxy_http`, `mod_rewrite`, `mod_headers`
- Python 3.9+ with `qp2_env` virtual environment (backend machine)
- Node.js 20.19+ or 22.12+ (required by Vite 7.x — Node 18 is **not** supported)
- Access to BeeGFS, MySQL, Redis from the backend machine

> **Note:** If the Apache server only has Node 18, build the frontend on the beamline machine (which has a newer Node) and copy the `dist/` folder to the Apache server.

## 1. Backend Setup

### Install dependencies

```bash
cd /mnt/beegfs/qxu/data-analysis/qp2
/mnt/beegfs/qxu/data-analysis/qp2_env/bin/pip install -e ".[auth]"
```

### Install systemd service

```bash
sudo cp web_app/qp2-web-backend.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now qp2-web-backend
```

The service file (`qp2-web-backend.service`):
- Runs uvicorn on `127.0.0.1:8000` (localhost only — not exposed to network)
- 2 worker processes
- Auto-generates `QP2_JWT_SECRET` on first start (persisted to `.jwt_secret` file)
- Sets `QP2_DATA_DIR`, `QP2_CORS_ORIGINS`, `PYTHONPATH`

### Environment variables

Set in the service file or `/mnt/beegfs/qxu/data-analysis/qp2/.env`:

| Variable | Default | Description |
|----------|---------|-------------|
| `QP2_JWT_SECRET` | **Required** (auto-generated by service) | JWT signing key. App crashes on startup if unset (except when `QP2_ENV=test`). Persisted via `.jwt_secret` file by `ExecStartPre` in the service. |
| `QP2_DATA_DIR` | `/mnt/beegfs/DATA` | Root directory for HDF5 file serving |
| `QP2_CORS_ORIGINS` | `https://www.gmca.aps.anl.gov` | Allowed CORS origins |
| `QP2_ENV` | (unset) | Set to `test` to enable test credentials and non-secure cookies |

> **Important:** If deploying without the systemd service file, you must generate and set `QP2_JWT_SECRET` manually:
> ```bash
> python3 -c "import secrets; print(secrets.token_urlsafe(32))"
> export QP2_JWT_SECRET="<output>"
> ```

### Verify backend

```bash
sudo systemctl status qp2-web-backend
curl http://127.0.0.1:8000/  # Should return JSON
```

## 2. Frontend Build

**Option A: Build on the beamline machine** (recommended if Apache server has Node < 20)

```bash
# On beamline machine
cd /mnt/beegfs/qxu/data-analysis/qp2/web_app/frontend
npm install
VITE_BASE_PATH=/data_portal/ VITE_API_URL=/data_portal/api npm run build

# Copy dist to Apache server
scp -r dist/ www.gmca.aps.anl.gov:/path/to/data_portal/
```

**Option B: Build on the Apache server** (requires Node.js 20.19+)

```bash
cd /path/to/qp2/web_app/frontend
npm install
VITE_BASE_PATH=/data_portal/ VITE_API_URL=/data_portal/api npm run build
```

Both options create a `dist/` folder with static files (HTML, JS, CSS). The `VITE_BASE_PATH` ensures all asset URLs are prefixed with `/data_portal/`.

## 3. Apache Configuration

### Enable required modules

```bash
sudo a2enmod proxy proxy_http rewrite headers
```

### Add configuration

Append the contents of `qp2-web-apache.conf` to your existing Apache vhost config for `www.gmca.aps.anl.gov`, or include it:

```apache
Include /mnt/beegfs/qxu/data-analysis/qp2/web_app/qp2-web-apache.conf
```

The config file (`qp2-web-apache.conf`):
- Serves frontend static files from `dist/` under `/data_portal/`
- SPA fallback (all non-file routes → `index.html`)
- Proxies `/data_portal/api/*` to backend on `127.0.0.1:8000` (including `/login`, `/logout`)
- SSE-friendly chat proxy with chunked encoding
- Security headers: HSTS, CSP, X-Content-Type-Options, X-Frame-Options, Referrer-Policy

### Restart Apache

```bash
sudo apachectl configtest
sudo systemctl restart apache2
```

## 4. Security

### IP-based access control

The backend enforces IP restrictions at login:
- **Staff** — allowed from any IP
- **Facility network** (10.*.*.*, 164.54.*.*) — always allowed
- **Remote users** — checked against `remote_ip_list` in their ESAF groups (gmca_accounts database)

### Authentication

- Kerberos/LDAP authentication against facility directory
- JWT tokens (24-hour expiry) stored in **HttpOnly, Secure** cookies (not in `localStorage`)
- Login rate limiting: 10 attempts per IP per 60 seconds
- Server-side token revocation on logout (in-memory, resets on restart)
- Security headers: HSTS, X-Content-Type-Options, X-Frame-Options, Referrer-Policy, Content-Security-Policy
- Cross-Origin headers: COOP (`same-origin`) and COEP (`require-corp`) set by the backend middleware for Mol* 3D viewer compatibility
- Install auth libraries: `pip install -e ".[auth]"` (ldap3, gssapi)
- See `LOGIN_FLOW.md` for detailed authentication flow documentation

### CORS

Update `QP2_CORS_ORIGINS` in the service file to match your domain:
```
Environment="QP2_CORS_ORIGINS=https://www.gmca.aps.anl.gov"
```

```bash

git pull

# Rebuild frontend if frontend changed
cd qp2/web_app/frontend
VITE_BASE_PATH=/data_portal/ VITE_API_URL=/data_portal/api npm run build
```

## 7. Development Mode

For local development with hot-reload:

```bash
cd /mnt/beegfs/qxu/data-analysis/qp2/web_app
./start.sh
```

This runs both backend (uvicorn with `--reload`) and frontend (vite dev server) on localhost.
